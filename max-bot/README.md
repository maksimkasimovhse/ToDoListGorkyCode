# Бот MAX

Бот планировщика в мессенджере MAX:

- **уведомления** о каждой встрече и напоминании — за 15 минут до начала и в момент начала;
- **утренняя сводка** — план на день, по умолчанию в 07:30, время настраивается;
- **тихие часы** — в это время бот молчит, а всё наступившее присылает сразу после их окончания;
- **создание задач, напоминаний и встреч кнопками** — меню, календарь, выбор часа и минут, длительность, участники, место;
- обычный текст уходит ассистенту, как в чат на сайте: «Напомни завтра в 10 позвонить Ивану».

О задачах бот не уведомляет: только о встречах и напоминаниях. Встречи на весь день попадают в утреннюю сводку.

## Архитектура

```
MAX ⇄ GET /updates (long polling) ⇄ max-bot ──HTTP──▶ backend :8080  (тот же API, что у сайта)
                                       ▲                    │
                                       │ XREADGROUP         │ диспетчер раз в 5 с
                                       └── planner:notify:max ◀── таблица notifications ◀── триггер на items
```

**Расписание считает бэкенд, а не бот.**
- Триггер `items_sync_notifications` (миграция `00006`) при каждом изменении записи пересчитывает строки `notifications`: `soon` за 15 минут и `now` в момент начала. Это срабатывает для любого изменения: правки на сайте, ассистента, отмены действия, переноса.
- Диспетчер в бэкенде раз в `NOTIFY_INTERVAL` забирает наступившие строки (`FOR UPDATE SKIP LOCKED`, поэтому можно запустить несколько экземпляров) и кладёт доставку в Redis Stream `planner:notify:max`.
- Бот отправляет сообщение и подтверждает доставку: `POST /internal/notifications/{id}/ack`.

**Уведомления не теряются.**
- Неподтверждённое уведомление через `NOTIFY_ACK_TIMEOUT` (5 мин) снова попадает в очередь.
- Строку потока бот подтверждает (`XACK`) только после отправки, а повтор отсекается отметкой `max:sent:<id>`.
- Если бэкенд или бот лежали, уведомление «в момент» придёт позже с пометкой об опоздании.
- «Скоро» о событии, которое уже началось, не отправляется.

**Правила «скоро»:**
- встреча, созданная меньше чем за 15 минут до начала, получает «скоро» сразу, если до начала больше минуты;
- напоминание, поставленное или отложенное меньше чем на 15 минут, присылает только «в момент»: время пользователь только что задал сам.

**Тихие часы:**
- уведомление, наступившее в тихие часы, откладывается до их конца (`held`);
- «скоро» о событии, которое начнётся раньше конца тихих часов, отменяется: вместо него придёт «началось»;
- сводка, попавшая в тихие часы, тоже придёт в момент их окончания.

**Сводка:**
- не больше одной в день;
- если бэкенд был выключен в её время, сводка придёт в течение 4 часов после.

### Привязка аккаунта

Бот работает от имени пользователя с отдельной долгоживущей сессией (`CHANNEL_SESSION_TTL`, по умолчанию год).
- **По ссылке с сайта.** ⚙️ Настройки → «Подключить MAX» выдаёт одноразовую ссылку `https://max.ru/<бот>?start=<код>`, код действует 10 минут. Без `MAX_BOT_URL` сайт показывает код, его отправляют боту командой `/link <код>`.
- **По логину и паролю в боте.** Сообщение с паролем бот сразу удаляет.
- **Отвязка.** `/logout` в боте отзывает сессию. Повторная привязка отзывает прежнюю.

Маршруты бота `/internal/*` закрыты общим секретом `Authorization: Bot <BOT_SERVICE_TOKEN>`. Без него они отвечают 401.

| Маршрут | Кто вызывает | Что делает |
|---|---|---|
| `GET/PATCH /api/notification-settings` | сайт, бот (Bearer) | `digest_enabled`, `digest_time`, `quiet_enabled`, `quiet_start`, `quiet_end` |
| `GET /api/channels` | сайт | привязанные мессенджеры |
| `POST /api/channels/max/link-code` | сайт | одноразовый код и ссылка на бота |
| `POST /internal/channels/max/link` | бот | `{external_id, code}` или `{external_id, login, password}` → токен |
| `GET/PATCH/DELETE /internal/channels/max/{id}` | бот | состояние, вкл/выкл уведомлений, отвязка |
| `POST /internal/notifications/{id}/ack` | бот | `{status: sent\|failed, disable_channel}` |

| Файл | Что делает |
|---|---|
| `bot.mjs` | точка входа: цикл `GET /updates`, потребитель потока, остановка по SIGTERM |

| `settings.mjs` | экран уведомлений: вкл/выкл, время сводки, тихие часы |
| `ui.mjs` | кнопки, меню, календарь, часы и минуты |

## Запуск

1. Подключитесь к платформе MAX для партнёров. Это доступно юрлицам, ИП и самозанятым — резидентам РФ, после верификации и модерации бота. Создайте бота и скопируйте токен: business.max.ru → Чат-боты → ⋮ → Настройки.
2. Придумайте общий секрет не короче 32 символов, например `openssl rand -hex 24`. Пропишите его как `BOT_SERVICE_TOKEN` в корневой `.env`. Там же задайте `MAX_BOT_URL=https://max.ru/<имя_бота>`.
3. Создайте `max-bot/.env` по образцу `.env.example`: `MAX_BOT_TOKEN` и тот же `BOT_SERVICE_TOKEN`.
4. Запустите:

```bash
docker compose up -d --build --wait     # в корне репозитория: бэкенд с диспетчером уведомлений
cd max-bot && docker compose up -d
docker compose logs -f                  # строка «max bot started»
```

### Проверка без настоящего MAX

```bash
# в max-bot/.env: MAX_API_URL=http://fake-max:9900, MAX_BOT_TOKEN=любое значение
docker compose -f compose.yaml -f compose.dev.yaml up -d
curl -X POST localhost:9900/_push -H 'Content-Type: application/json' \
  -d '{"update_type":"bot_started","user":{"user_id":555},"payload":"<код с сайта>"}'
curl localhost:9900/_sent   # что бот отправил
```

| Переменная | По умолчанию | Назначение |
|---|---|---|
| `MAX_BOT_TOKEN` | обязательна | токен бота MAX |
| `BOT_SERVICE_TOKEN` | обязательна | общий секрет с бэкендом |
| `MAX_API_URL` | `https://platform-api2.max.ru` | адрес MAX API |
| `MAX_ALLOWED_USERS` | пусто — все | user_id MAX через запятую |
| `BACKEND_URL` | `http://backend:8080` | адрес API |
| `REDIS_URL` | `redis://redis:6379/0` | Redis приложения |
| `TIMEZONE` | `Europe/Moscow` | пояс дат в мастерах и подписях |

Бэкенд: `BOT_SERVICE_TOKEN`, `MAX_BOT_URL`, `CHANNEL_SESSION_TTL` (8760h), `NOTIFY_INTERVAL` (5s), `NOTIFY_ACK_TIMEOUT` (5m).

## Ограничения

- Long polling MAX рекомендует только для разработки. В проде лучше webhook (`POST /subscriptions`), для этого нужен публичный HTTPS-адрес.
- Пояс дат в мастерах один на бота (`TIMEZONE`). Расписание уведомлений и сводки бэкенд считает в поясе пользователя (`users.timezone`).
- Не больше 2 сообщений в секунду в один диалог (ограничение MAX). При 429 бот повторяет запрос.
