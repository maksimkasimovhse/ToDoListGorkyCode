# Noti — фронтенд

Веб-интерфейс голосового ассистента задач, напоминаний и встреч. Пользовательские сценарии и общий запуск описаны в [общем README](../README.md). Здесь — как устроен интерфейс, как он работает с бэкендом и как его разрабатывать.

Чистые JavaScript (ES-модули), HTML и CSS: без сборки, фреймворков и npm-зависимостей. Голос — встроенные Web Speech API и `speechSynthesis` браузера.

## Возможности

| Область | Что умеет |
|---|---|
| **Чат с ассистентом** | Текст и голос («Напомни завтра в 10 позвонить Ивану»). Уточнения приходят формой (дата, время, название) или кнопками «Да» / «Нет»; отвечать можно и словами: «в 17», «завтра», «отмена» |
| **Озвучка** | Ответы читаются вслух. По умолчанию включается после голосового ввода, переключатель «Озвучивать ответы» в шапке чата |
| **Мои записи** | Календарь на неделю или месяц, просроченные задачи и задачи без срока. Кнопка «На весь экран» раскрывает шкалу времени недели и сетку месяца |
| **Последнее** | Недавно созданные записи, поиск (по словам и по смыслу) и фильтр по типам |
| **Ручная правка** | «+» создаёт запись, двойной клик по карточке открывает редактирование, галочка отмечает выполнение, есть удаление. Любое действие можно отменить из всплывающего сообщения |
| **Напоминания и уведомления** | Сообщение в чате со звуком и кнопками «Сделано» / «Через 15 минут», а также уведомления браузера за 15 минут до встречи или напоминания и в момент начала |
| **Бот MAX** | Пункт «Подключить MAX» в меню профиля выдаёт одноразовую ссылку на бота; там же отвязка |
| **Настройки** | Имя ассистента, мужской или женский голос, включение уведомлений браузера |

Типы записей окрашены по легенде макета: встречи зелёные, задачи фиолетовые, напоминания жёлтые.

## Запуск

Обычно фронт запускается вместе со всем приложением, из корня репозитория:

```bash
docker compose up -d --build --wait
```

Откройте http://localhost:8080 и войдите как `demo1` / `DemoPass1!` или `demo2` / `DemoPass2!`: кнопки под формой входа подставляют эти данные.

Страницу и API отдаёт Go-бэкенд с одного адреса, поэтому CORS и отдельный веб-сервер не нужны. Папка `web/` копируется в образ при сборке ([Dockerfile](../backend/Dockerfile)), так что после правок пересоберите бэкенд и обновите страницу без кеша:

```bash
docker compose up -d --build backend   # затем Ctrl+Shift+R в браузере
```

Чтобы не пересобирать образ на каждую правку, запустите Go локально ([README бэкенда](../backend/README.md#запуск-только-бэкенда)): по умолчанию он раздаёт `../web` прямо с диска, и для правок достаточно обновить страницу.

### Без бэкенда

Интерфейс можно открыть на встроенной заглушке API. Поставьте `MODE: 'mock'` в [js/config.js](js/config.js) и выполните в папке `web/`:

```bash
python3 -m http.server 8000
```

Откройте http://localhost:8000. Вход в этом режиме не нужен.

### Браузеры

- Голосовой ввод работает в Chrome, Edge и Safari. В Firefox доступен только текстовый ввод.
- Микрофону, уведомлениям и ES-модулям нужен защищённый контекст: `localhost` или https. Ни с `file://`, ни по IP-адресу в локальной сети через http они не заработают.
- Вёрстка адаптивна: на ширине до 1100 и до 760 пикселей панели перестраиваются.

## Конфигурация

Все настройки собраны в [js/config.js](js/config.js):

| Параметр | По умолчанию | Назначение |
|---|---|---|
| `MODE` | `'backend'` | Источник данных, см. ниже |
| `API_BASE` | `''` | Адрес API, если он на другом домене. Тогда бэкенду нужен CORS |
| `MESSAGE_TIMEOUT_MS` | `20000` | Сколько ждать приёма сообщения ассистентом |
| `DEMO_ACCOUNTS` | demo1, demo2 | Кнопки под формой входа. **Для публичной установки оставьте `[]`** |

| `MODE` | Поведение |
|---|---|
| `backend` | Только настоящий API. Рабочий режим |
| `auto` | Настоящий API, а маршруты, которых в бэкенде нет, и все запросы при недоступном бэкенде обслуживает заглушка. Отсутствующий маршрут запоминается до перезагрузки страницы |
| `mock` | Только заглушка из `js/mock/`, бэкенд не нужен |

Когда отвечает не только бэкенд, в шапке появляется бейдж: «Заглушка», «Бэкенд + заглушка (N)» со списком маршрутов во всплывающей подсказке или «Бэкенд не отвечает», если `/healthz` недоступен. Каждый переход на заглушку пишется в консоль строкой `[api] GET /api/items → заглушка`.

## Как фронт работает с бэкендом

Все запросы идут через [js/api.js](js/api.js). Режим меняет только то, кто отвечает: заглушка принимает те же пути и форматы, поэтому код вызовов от режима не зависит.

**Вход** ([backend/docs/auth.md](../backend/docs/auth.md)). `POST /api/auth/login` выдаёт Bearer-токен. Токен и срок сессии хранятся в `localStorage`, поэтому вход переживает перезагрузку. При ответе `401 unauthorized` страница возвращает на форму входа с сообщением «Сессия закончилась». «Выйти» отзывает токен на сервере и очищает экран.

**Сообщения ассистенту** ([async-contract.md](../backend/docs/async-contract.md)). Обработка асинхронная:

1. `POST /api/message` возвращает `202` и `message_id`.
2. Фронт раз в секунду опрашивает `GET /api/messages/{id}`, пока статус `processing`.
3. Готовый ответ рисуется в чате по типу: `done`, `clarify`, `choose`, `confirm`, `conflict`, `results`, `info` или `error`.

**Уточнения** ([dialogue-flow.md](../backend/docs/dialogue-flow.md)). В статусе `awaiting_input` или `awaiting_confirmation` бэкенд ждёт ответа и не принимает новых сообщений (`409 conversation_busy`). Чат показывает форму или кнопки, а ответ уходит в `POST /api/messages/{id}/answer` полями (`date`, `time`, `title`, `duration_min` или `confirmed`), не текстом. Фразы вроде «в 17», «завтра», «да» в эти поля переводит [js/answer.js](js/answer.js). «Отмена» вызывает `POST /api/messages/{id}/cancel`. Если перезагрузить страницу посреди сценария, форма восстановится из `pending_messages` в `GET /api/history`.

**Записи.** Список: `GET /api/items`, `/undated` и `/search`, каждый запрос с поясом пользователя. Изменения: `POST`, `PATCH` и `DELETE /api/items`. Ответы на изменения содержат `undo_token`, а «Отменить» и «Вернуть» отправляют его в `POST /api/undo`: запись возвращается с тем же id. При пересечении встреч бэкенд отвечает `409 meeting_conflict`, и фронт предлагает сохранить запись всё равно.

**Время.** «Сейчас» и часовой пояс берутся из `GET /api/me`, поэтому «сегодня» на фронте всегда совпадает с сервером, даже если часы на демо заморожены ([js/time.js](js/time.js)).

## Что фронт делает сам

Это логика в браузере поверх обычных запросов:

- **Срабатывание напоминаний** ([js/reminders.js](js/reminders.js)). Пока страница открыта, она следит за открытыми напоминаниями и в нужный момент пишет в чат «Напоминаю: …», играет звук и озвучивает. Напоминания, наступившие, пока страница была закрыта, приходят одним сообщением «Пока вас не было: …». Показанные напоминания запоминаются в `localStorage` и после перезагрузки не повторяются.
- **Уведомления браузера** ([js/notifications.js](js/notifications.js), правила — [js/schedule.js](js/schedule.js)). За 15 минут до напоминания или встречи и в момент начала, пока открыта хотя бы фоновая вкладка. Встречи на весь день не уведомляют. Если вкладка закрыта, уведомления доставляет [бот MAX](../max-bot/README.md): расписание для него считает бэкенд.
- **Просроченные задачи.** Бэкенд отдаёт пустой `overdue`, поэтому фронт берёт открытые задачи со сроком раньше сегодняшнего дня.
- **Порядок «Последних».** Бэкенд сортирует по сроку записи, поэтому фронт запрашивает 100 записей и упорядочивает их по `created_at`.
- **Настройки ассистента.** Имя и голос хранятся в браузере: профиля для них на сервере нет.

```text
index.html            разметка: вход, три панели, диалоги настроек и записи
css/styles.css        все стили, адаптивная вёрстка
js/
  app.js              точка входа: связывает модули, отправка сообщений, озвучка, действия с записями
  config.js           режим, адрес API, тестовые аккаунты
  api.js              клиент API: polling сообщений, переход на заглушку, бейдж источника
  auth.js, login.js   сессия в localStorage и страница входа
  chat.js             история диалога и отрисовка ответов всех типов
  answer.js           ответ словами или голосом → поля формы бэкенда
  calendar.js         панель «Мои записи»: неделя и месяц, полноэкранный режим
  cards.js            карточки записей на шкале времени
  recent.js           панель «Последнее»: поиск и фильтры
  item-form.js        окно создания и редактирования записи
  items.js, time.js   подписи записей, даты в поясе пользователя
  reminders.js        срабатывание напоминаний в чате
  notifications.js    уведомления браузера
  schedule.js         правила уведомлений (без DOM)
  settings.js         имя ассистента и голос
  voice.js            распознавание и синтез речи
  max-link.js         подключение и отвязка бота MAX
  dom.js              мелкие DOM-помощники
  mock/               заглушка бэкенда
```

## Заглушка

`js/mock/` эмулирует API целиком: правила разбора фраз (`nlu.js`), логику диалога (`assistant.js`), поиск (`queries.js`) и «базу» в `localStorage` (`store.js`). Она нужна для вёрстки и демонстрации без Docker и ключей GigaChat.

- Время заморожено: **четверг, 29 октября 2026, 12:00, Москва**.
- Заранее созданы три записи для сценариев поиска: задача «подготовить слайды к защите», выполненная задача «подписать договор аренды» и прошедшая встреча с Иваном 20 октября.
- Фразы разбираются правилами, а не моделью: формулировки из ФТ и близкие к ним работают, произвольные — не всегда.
- Помощники в консоли браузера: `__mock.reset()` возвращает начальные данные, `__mock.fireReminder()` имитирует срабатывание напоминания.

## Если не работает

- **Страница не обновилась после правок.** Пересоберите бэкенд (`docker compose up -d --build backend`) и обновите страницу с Ctrl+Shift+R.
- **Ошибка в чате или «Сервер не ответил вовремя».** Проверьте, что запущен `ml-worker` и задан ключ GigaChat: `docker compose logs ml-worker`.
- **Нет кнопки микрофона или уведомлений.** Откройте страницу через `localhost` или https в Chrome, Edge или Safari и проверьте разрешения сайта в браузере.
- **В шапке «Бэкенд не отвечает».** Бэкенд не запущен или `/healthz` недоступен: `docker compose ps`, `docker compose logs backend`.
- **Снова просит войти.** Сессия истекла или отозвана. Войдите заново. Диагностика авторизации — в [README бэкенда](../backend/README.md#диагностика).
