# Голосовой ассистент — фронтенд

Чистые JS (ES-модули) и CSS, без сборки и зависимостей. Ходит в бэкенд из `../backend`; то, чего в бэкенде ещё нет, отвечает заглушка `js/mock/` в форматах `contracts.md` (v0.2). Заглушка проходит сценарии приёмки из ФТ, раздел 16.

## Запуск

Всё приложение запускается из корня через Docker Compose: см. [общую инструкцию](../README.md), страница на http://localhost:8080. Бэкенд сам отдаёт эту папку, поэтому страница и API на одном адресе, CORS и отдельный сервер не нужны.

Без бэкенда фронт можно открыть на заглушке: поставьте `MODE: 'mock'` в `js/config.js` и запустите в этой папке:

```bash
python3 -m http.server 8000
```

Откройте http://localhost:8000. Голосовой ввод работает в Chrome, Edge и Safari. Нужен `localhost` или https, с `file://` модули и микрофон не работают.

Файлы `web/` попадают в образ бэкенда при сборке: после правок пересоберите его (`docker compose up -d --build backend`) и обновите страницу с Ctrl+Shift+R — бэкенд не запрещает браузеру кешировать модули.

## Бэкенд или заглушка

`MODE` в `js/config.js`:

| Режим | Поведение |
|---|---|
| `auto` | запрос идёт в бэкенд. Если маршрута там нет (404/405 от роутера без тела ошибки из контракта 2.7) или бэкенд не запущен (502/503/504 от прокси, сетевая ошибка), отвечает заглушка. Отсутствующий маршрут запоминается до перезагрузки страницы. Как только бэкенд реализует эндпоинт, фронт начнёт ходить в него сам |
| `backend` (по умолчанию) | только бэкенд. Чего в нём ещё нет (`/api/me`, поток напоминаний, `/api/undo`), показывается как «пока не поддерживается» или молча пропускается |
| `mock` | только заглушка, бэкенд не нужен |

Бейдж в шапке показывает источник: «Бэкенд + заглушка (N)» — во всплывающей подсказке список маршрутов на заглушке, «Бэкенд не отвечает» — `/healthz` недоступен. Когда всё отвечает бэкенд, бейджа нет. В консоли каждый переход на заглушку пишется строкой `[api] GET /api/items → заглушка`.

Сообщения ассистенту бэкенд обрабатывает асинхронно (`backend/docs/async-contract.md`): `POST /api/message` отвечает `202` с `message_id`, фронт раз в секунду опрашивает `GET /api/messages/{id}`, пока ответ не готов.

**Уточнения и подтверждения** (`backend/docs/dialogue-flow.md`): пока сценарий ждёт ответа (`awaiting_input` / `awaiting_confirmation`), бэкенд не принимает новых сообщений (`409 conversation_busy`). Вопрос приходит с `input_token`; чат рисует под ним форму (время, дата или название) или кнопки «Да»/«Нет», а ответ уходит в `POST /api/messages/{id}/answer` полями, не текстом. Текст и голос («в 17», «завтра», «да», «отмена») разбирает `js/answer.js` в те же поля. «Отмена» — `POST /api/messages/{id}/cancel`. После перезагрузки страницы форма восстанавливается из `pending_messages`. Заглушка отвечает сразу; `api.sendMessage` прячет разницу и в обоих случаях отдаёт готовый ответ. Если страницу перезагрузили во время ответа, фронт дожидается его по `pending_messages` из `/api/history`.

Когда бэкенд работает, но маршрута в нём нет, заглушка отвечает не везде. Действия над записями (`PATCH`/`DELETE /api/items/:id`, `/api/undo`) показывают «пока не поддерживается бэкендом»: заглушка не знает настоящих записей. 

Пока часть маршрутов на заглушке, данные живут в двух местах: заглушка хранит свои в localStorage, бэкенд — в PostgreSQL. Например, если `GET /api/items` уже в бэкенде, а `/api/message` ещё нет, созданное через чат в списке не появится. Это нормально для переходного периода.

## Вход

Бэкенд требует вход (`backend/docs/auth.md`): все запросы к API идут с заголовком `Authorization: Bearer <токен>`. При запуске фронт без сохранённой сессии показывает страницу входа ([login.js](js/login.js)). Тестовые аккаунты локального прототипа: `demo1` / `DemoPass1!` и `demo2` / `DemoPass2!`; под окном входа две кнопки подставляют их данные (список в `DEMO_ACCOUNTS` в `js/config.js`, для публичной установки его нужно очистить). У каждого пользователя свои записи и свои чаты.

- Токен и срок сессии лежат в `localStorage` ([auth.js](js/auth.js)), после перезагрузки страницы вход сохраняется.
- «Выйти» — в меню под иконкой профиля: токен отзывается на сервере, чат и списки на экране очищаются.
- Если сервер ответил 401 `unauthorized` (токен истёк или отозван), страница возвращает на вход с сообщением «Сессия закончилась».
- Режим `MODE: 'mock'` (без бэкенда) обходится без входа.

## Что фронт делает сам

Бэкенд этого не умеет, поэтому логика на фронте поверх обычных запросов:

- **Напоминания срабатывают** ([reminders.js](js/reminders.js)): пока страница открыта, она следит за открытыми напоминаниями из `GET /api/items`, в нужный момент пишет в чат «Напоминаю: …» с кнопками «Сделано» и «Через 15 минут», играет звук и озвучивает. Если напоминание наступило, пока страницы не было, при открытии одно сообщение «Пока вас не было: …». Какие напоминания уже показаны, помнит `localStorage` (`fired_reminders`), после перезагрузки они не повторяются. Время проверяется каждую минуту и после любого изменения записей.
- **«Просрочено»** в «Сегодня» и «Ближайших»: бэкенд всегда отдаёт пустой `overdue`, поэтому берём открытые задачи со сроком раньше сегодняшнего дня и оставляем те, что он пометил `computed.overdue`.
- **«Последнее» по времени создания**: бэкенд сортирует по сроку и `sort` не понимает, поэтому берём 100 записей и упорядочиваем по `created_at` в браузере.

Откат («Вернуть», «Отменить») идёт через `POST /api/undo` по `undo_token` из ответов `POST/PATCH/DELETE /api/items` и из ответов ассистента: запись возвращается с тем же id.

## Структура

| Файл | Что делает |
|---|---|
| `js/config.js` | `MODE` (бэкенд или заглушка), адрес API, тайм-аут запроса |
| `js/api.js` | клиент API по разделу 2 контрактов; маршруты, которых нет в бэкенде, переадресует в `js/mock/server.js` с теми же путями |
| `js/app.js` | связывает части: отправка сообщений, озвучка, выбор записи, напоминания |
| `js/auth.js`, `js/login.js` | сессия входа в браузере и страница входа |
| `js/reminders.js` | срабатывание напоминаний на фронте |
| `js/answer.js` | ответ словами или голосом на вопрос ассистента («в 17», «да», «отмена») → поля формы бэкенда |
| `js/settings.js` | имя ассистента и голос озвучки |
| `js/chat.js` | история диалога, отрисовка ответов всех типов: `done`, `clarify`, `choose`, `confirm`, `conflict`, `results`, `info`, `error` |
| `js/calendar.js` | правая панель «Мои записи»: неделя (с просроченными и задачами без срока) и месяц; во весь экран — шкала времени и сетка месяца |
| `js/cards.js` | карточки записей: галочка, удаление, двойной клик — редактирование |
| `js/recent.js` | левая панель «Последнее»: поиск и фильтр по типам |
| `js/voice.js` | распознавание (Web Speech API, ru-RU) и озвучка (speechSynthesis) |
| `js/items.js`, `js/time.js` | подписи записей и даты в поясе пользователя |
| `js/mock/` | заглушка бэкенда: разбор фраз правилами, логика диалога, «база» в localStorage |

## Заглушка

- Время в заглушке заморожено на моменте из ФТ: **четверг, 29 октября 2026, 12:00, Москва**. Когда заглушка отвечает целиком (бэкенд не запущен или `MODE: 'mock'`), фронт берёт «сейчас» из её `/api/me`, и календарь показывает 29 октября как сегодня.
- Заранее есть три записи для сценариев поиска 15–17: задача «подготовить слайды к защите», выполненная задача «подписать договор аренды» и прошедшая встреча с Иваном 20 октября.
- Фразы разбираются правилами, а не LLM. Работают формулировки из ФТ и близкие к ним, но не любые.
- Помощники в консоли браузера:
  - `__mock.reset()` возвращает начальные данные;
  - `__mock.fireReminder()` имитирует срабатывание напоминания.

## Переход на бэкенд

Ничего не нужно: в режиме `auto` фронт переходит на реализованные маршруты сам. Когда бэкенд готов целиком, `MODE: 'backend'` и при необходимости `API_BASE`, если API на другом адресе без прокси (тогда бэкенду нужен CORS).

## Что фронт предполагает сверх контракта v0.2

Это предложения в контракт. Их надо согласовать с бэкендом.

1. **`GET /api/items?sort=-created_at&limit=20&types=…`** — последние созданные записи для левой панели. Сейчас в контракте такого нет.
2. **`now` в ответе `GET /api/me`** — текущее время сервера. Нужно, чтобы «сегодня» на фронте совпадало с сервером, если часы на демо заморожены. Без поля фронт берёт время браузера.
3. **`session_id` создаёт фронт** (`s_<uuid>`) и хранит в localStorage. «Новый диалог» вызывает `POST /api/session/reset` и создаёт новый id.
4. **Ответ `GET /api/history`** — `{ "history": [ … ] }`. Голый массив тоже принимается.
5. **Токен для `GET /api/stream`** — в `?token=`, потому что EventSource не умеет отправлять заголовок `Authorization`.
6. **Нажатие кнопки** отправляет и `choice`, и `text` с подписью кнопки, чтобы она попала в историю.
7. **`POST /api/undo`** отвечает в формате `/api/message`. Если в ответе есть `reply`, он показывается в чате.
8. **Пустую речь и ошибки микрофона** фронт обрабатывает сам и на сервер не отправляет. Код `empty_speech` остаётся на случай, если `text` всё же пустой.

## Решения по макету

- Цвета типов взяты по легенде макета: встречи зелёные, задачи фиолетовые, напоминания жёлтые. На макете карточки окрашены не по легенде.
- Пустой четвёртый фильтр с синей точкой убран: в модели только три типа и нет своих меток.
- Правая панель называется «Мои записи», как в ФТ: в ней не только задачи.
- Добавлены элементы, которых нет на макете: переключатель «Озвучивать ответы» (обязателен по ФТ 3), «Новый диалог», галочка «выполнено» и удаление в списке, просроченные задачи, задачи без времени и со сроком-периодом.
