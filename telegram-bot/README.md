# Telegram-бот

Второй клиент ассистента рядом с сайтом. Пишете боту так же, как в чат на сайте: «Напомни завтра в 10 позвонить Ивану», «Что у меня завтра?». Бот отвечает, задаёт уточняющие вопросы, показывает кнопки «Да/Нет» и присылает уведомления за 15 минут до встреч и напоминаний и в момент начала.

## Архитектура

```
Telegram ⇄ long polling (getUpdates) ⇄ telegram-bot ──HTTP──▶ backend :8080 (тот же API, что у сайта)
                                            │
                                            └── Redis приложения, ключи tg:*
```

- **Тонкий клиент.** Разбор фраз, даты, конфликты и сохранение остаются в бэкенде и ML. Бот переводит сообщения Telegram в вызовы [API](../backend/docs/async-contract.md) и отрисовывает ответы. Бэкенд не знает, что с ним говорит бот.
- **Long polling.** Публичный адрес и HTTPS не нужны, бот работает и с localhost.
- **Общий код с сайтом.** Модули `web/js` монтируются в контейнер только для чтения:
  - `answer.js` — разбор ответов на уточнения: «в 17», «завтра», «да», «отмена»;
  - `items.js` и `time.js` — подписи записей, группировка по дням, пояс;
  - `schedule.js` — когда слать уведомления.

  Поведение совпадает с сайтом без дублирования кода.
- **Состояние в Redis** (префикс `tg:`):
  - номер диалога (`/new` начинает новый);
  - токен входа;
  - отметки отправленных уведомлений — сутки, чтобы после перезапуска не было повторов;
  - `offset` последнего апдейта.
- **Начатое уточнение** бот после перезапуска восстанавливает из `GET /api/history`.
- **Повторы безопасны.** `client_message_id` = `tg_<update_id>`: повторно доставленный апдейт бэкенд не выполнит второй раз.

| Файл | Что делает |
|---|---|
| `bot.mjs` | точка входа: цикл `getUpdates`, команды, остановка по SIGTERM |
| `dialog.mjs` | диалог чата: текст, кнопки, команды; сообщения одного чата по очереди |
| `backend.mjs` | клиент API: сообщение и опрос, `/answer`, `/cancel`, история, записи, вход |
| `render.mjs` | ответ ассистента → HTML-текст и клавиатуры Telegram |
| `notify.mjs` | уведомления раз в 30 секунд |
| `auth.mjs` | `/login`, `/guest`, `/logout` |
| `store.mjs` | Redis (и версия в памяти для тестов) |
| `telegram.mjs` | Bot API через `fetch`, повтор при 429 и сетевых сбоях |

## Запуск

1. Создайте бота у [@BotFather](https://t.me/BotFather) командой `/newbot` и скопируйте токен.
2. Создайте `telegram-bot/.env` по образцу `.env.example` и вставьте токен.
3. Поднимите приложение, ML-заглушку и бота:

```bash
docker compose up -d --build --wait            # в корне репозитория
docker compose -f ml-stub/compose.yaml up -d   # без ML ассистент ответит ошибкой по тайм-ауту
cd telegram-bot && docker compose up -d
docker compose logs -f                         # строка «telegram bot started» с именем бота
```

Бот подключается к сети `backend_default` и ходит в `http://backend:8080`. Остановить: `docker compose down`.

| Переменная | По умолчанию | Назначение |
|---|---|---|
| `TELEGRAM_BOT_TOKEN` | обязательна | токен от @BotFather |
| `TELEGRAM_ALLOWED_USERS` | пусто — все | Telegram ID через запятую, кому бот отвечает |
| `BACKEND_URL` | `http://backend:8080` | адрес API |
| `REDIS_URL` | `redis://redis:6379/0` | Redis приложения |
| `TIMEZONE` | `Europe/Moscow` | пояс для дат и «сегодня» |

Свой Telegram ID подскажет, например, [@userinfobot](https://t.me/userinfobot).

## Команды

`/today`, `/tomorrow`, `/week` — планы; `/new` — новый диалог; `/notify` — включить или выключить уведомления; `/login`, `/guest`, `/logout` — вход; `/help`. Всё остальное пишется обычным текстом.

## Пользователи

- **`/login`** спрашивает логин и пароль и вызывает `POST /api/auth/login` ([контракт 2.6](../contracts%20(1).md)). Сообщение с паролем бот сразу удаляет. Токен уходит в каждый запрос как `Authorization: Bearer`.
- **`/guest`** создаёт нового тестового пользователя.
- **Пока входа в бэкенде нет**, бот работает без токена, то есть как общий демо-пользователь сайта, и говорит об этом.
- **Если токен перестал действовать** (401), бот сбрасывает привязку и предлагает войти снова.

## Проверка

```bash
docker run --rm -v "$PWD/..":/src:ro node:22-alpine sh -c "cp -r /src /app && cd /app/telegram-bot && npm ci && node --test"
```

Тесты в [bot.test.mjs](bot.test.mjs) работают с поддельными Telegram и бэкендом в памяти. Они проверяют:
- сообщение и ответ, экранирование HTML;
- уточнение «в 17» → `/answer {time:"17:00"}`;
- кнопку «Да» → `{confirmed:true}`;
- повтор апдейта без дубля;
- занятый диалог;
- восстановление уточнения после перезапуска;
- `/login` без поддержки на сервере;
- уведомления без повторов, кнопки «Сделано» и «Через 15 минут».

## Ограничения

- Только текст: на голосовое бот просит написать текстом. Следующий шаг — распознавание OGG через Whisper или SpeechKit.
- Работает только в личных сообщениях.
- Уведомления — опрос раз в 30 секунд, поэтому возможна задержка до 30 секунд.
- Отмена действия (`undo`) пока не поддерживается сервером: кнопка «Отменить» появится, когда бэкенд начнёт отдавать `undo_token`.
