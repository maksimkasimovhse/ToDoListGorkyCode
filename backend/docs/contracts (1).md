# Контракты голосового ассистента

Версия 0.2. Согласована с документом «Голосовой ассистент: функциональные требования» (далее **ФТ**).

**Как читать вместе:** ФТ описывает, *что* ассистент делает и отвечает. Этот документ описывает, *в каком формате* это передаётся между фронтендом, бэкендом и LLM-модулем. Если документы противоречат друг другу, по поведению главный ФТ, по формату — этот документ. Противоречие — повод поправить один из них.

Ссылки вида **[ФТ 5]** ведут на раздел ФТ, **FR-n** — на требование из его таблицы.

Открытые вопросы помечены **[решить]** и собраны в разделе 8.

---

## 0. Общие соглашения

| Что | Формат | Пример |
|---|---|---|
| Кодировка | JSON, UTF-8 | |
| Поля | `snake_case` | `start_at` |
| Нет значения | `null`, не пустая строка | |
| Дата без времени | `YYYY-MM-DD` | `2026-10-30` |
| Момент времени | ISO 8601 со смещением пользователя | `2026-10-30T15:00:00+03:00` |
| Хранение времени | в UTC, отдаётся в поясе пользователя **[ФТ 2]** | |
| Часовой пояс | IANA, берётся из браузера при первом входе и хранится в профиле **[ФТ 5]** | `Europe/Moscow` |
| Начало недели | понедельник **[ФТ 5]** | |
| ID | строка (UUID) | `"7f3c…"` |
| Периоды в запросах | `from` и `to` — моменты времени, `to` **не включается** | неделя: `2026-10-26T00:00+03:00` … `2026-11-02T00:00+03:00` |

Пример «сейчас» для всех примеров ниже — как в ФТ: **четверг, 29 октября 2026, 12:00, Europe/Moscow**.

## 1. Модель записи (Item) — по [ФТ 2]

Одна сущность для всех типов, поле `type` различает задачу, напоминание и встречу.

```json
{
  "id": "7f3c2a10-1b2c-4d5e-8f90-123456789abc",
  "user_id": "u_1",
  "type": "meeting",
  "title": "Встреча с командой",
  "source_text": "Добавь встречу с командой завтра в 15:00",

  "due_date": null,
  "due_at": null,
  "period_start": null,
  "period_end": null,

  "start_at": "2026-10-30T15:00:00+03:00",
  "end_at": "2026-10-30T16:00:00+03:00",
  "all_day": false,
  "participants": ["команда"],
  "location": null,

  "remind_at": null,
  "status": "scheduled",
  "recurrence": null,

  "created_at": "2026-10-29T12:00:05+03:00",
  "updated_at": "2026-10-29T12:00:05+03:00",
  "completed_at": null,
  "deleted_at": null,

  "computed": { "overdue": false, "occurrence": null }
}
```

### Поля по типам

| Поле | Задача | Напоминание | Встреча | Комментарий |
|---|---|---|---|---|
| `title` | ✔ | ✔ | ✔ | правила формирования **[ФТ 2]** |
| `source_text` | ✔ | ✔ | ✔ | исходная фраза как есть |
| `due_date` | один из трёх вариантов срока или ничего | — | — | «в пятницу» |
| `due_at` | | — | — | «в пятницу в 18» |
| `period_start`, `period_end` | | — | — | «до конца недели» → `period_start` = сейчас, `period_end` = вс 23:59 |
| `remind_at` | — | **обязательно** | необязательно | момент напоминания |
| `start_at`, `end_at` | — | — | **обязательно** | по умолчанию 60 минут **[ФТ 7]** |
| `all_day` | — | — | ✔ | «встреча на весь день» |
| `participants` | ✔ | — | ✔ | в именительном падеже: `["Иван"]` |
| `location` | — | — | ✔ | |
| `status` | `open` \| `done` | `open` \| `done` | `scheduled` \| `cancelled` | |
| `completed_at` | ✔ | ✔ | — | |
| `deleted_at` | ✔ | ✔ | ✔ | мягкое удаление, нужно для отмены (FR-15) |
| `recurrence` | ✔ | ✔ | ✔ | FR-14 |

У задачи заполнен **не больше одного** варианта срока: `due_date`, `due_at` или период.

### Вычисляемые поля (только в ответах, в базе не хранятся)

- `computed.overdue` — открытая задача, срок которой прошёл. Нужно фронту для подсветки.
- `computed.occurrence` — для вхождения повторяющейся записи: `{ "series_id": "…", "date": "2026-11-02" }`. Списки и поиск показывают конкретные вхождения **[ФТ 12]**.

### Повторение (FR-14)

```json
{ "freq": "weekly", "interval": 1, "weekdays": ["mon"], "month_day": null, "until": null }
```

`freq`: `daily` | `weekly` | `monthly`. «По будням» = `weekly` + `["mon","tue","wed","thu","fri"]`. «Каждое 5-е число» = `monthly` + `month_day: 5`. `until: null` — бессрочно.

## 2. API: фронтенд ↔ бэкенд

### 2.1 `POST /api/message` — сообщение ассистенту

**Запрос**

```json
{
  "client_message_id": "c_01HF3…",
  "session_id": "s_abc123",
  "text": "Поставь встречу с Иваном завтра",
  "input": "voice",
  "choice": null,
  "context": { "selected_item_id": null }
}
```

| Поле | Комментарий |
|---|---|
| `client_message_id` | уникален для каждого сообщения, генерирует фронт. Повтор с тем же id не обрабатывается второй раз и возвращает прежний ответ **[ФТ 15]** |
| `input` | `voice` \| `text` |
| `choice` | нажатие кнопки вместо слов: `{ "option_id": "opt_2" }`. Тогда `text` может быть `null` |
| `context.selected_item_id` | запись, по которой пользователь кликнул в списке; становится фокусом диалога **[ФТ 11]** |

**Ответ — общая обёртка**

```json
{
  "type": "done",
  "reply": "Добавил встречу с командой: завтра, пятница 30 октября, 15:00–16:00.",
  "speak": "Добавил встречу с командой: завтра, в пятницу тридцатого октября, в пятнадцать часов.",
  "items": [],
  "options": [],
  "data": {},
  "undo_token": null,
  "suggestions": []
}
```

| Поле | Комментарий |
|---|---|
| `type` | `done` \| `clarify` \| `choose` \| `confirm` \| `conflict` \| `results` \| `info` \| `error` |
| `reply` | текст для чата по правилам **[ФТ 14]** |
| `speak` | короткая версия для озвучки: без разметки, числа словами, длинные списки — количество и первые 3 **[ФТ 3]**. `null` → фронт озвучивает `reply` |
| `items` | записи для карточек (полная модель Item) |
| `options` | кнопки `{ "id", "label" }` |
| `data` | поля, специфичные для типа |
| `undo_token` | есть, если действие можно отменить (FR-15) |
| `suggestions` | подсказки-чипы |

Фронт **всегда** может показать хотя бы `reply`, даже если не знает тип.

### 2.2 Типы ответа

#### `done` — действие выполнено [ФТ 6, 7, 10]

```json
{
  "type": "done",
  "reply": "Перенёс встречу с Иваном: с 30 октября 15:00 на 31 октября 15:00.",
  "items": [ { "id": "a1", "type": "meeting", "title": "Встреча с Иваном", "start_at": "2026-10-31T15:00:00+03:00", "end_at": "2026-10-31T16:00:00+03:00", "status": "scheduled" } ],
  "options": [],
  "data": {
    "actions": [
      { "action": "updated", "item_id": "a1",
        "before": { "start_at": "2026-10-30T15:00:00+03:00", "end_at": "2026-10-30T16:00:00+03:00" },
        "after":  { "start_at": "2026-10-31T15:00:00+03:00", "end_at": "2026-10-31T16:00:00+03:00" } }
    ]
  },
  "undo_token": "undo_91ab",
  "suggestions": []
}
```

- `data.actions[].action`: `created` | `updated` | `deleted` | `completed` | `reopened` | `snoozed`.
- Несколько созданий в одной фразе **[ФТ 4]** — несколько элементов в `actions` и в `items`.
- Для `updated` всегда есть `before` и `after` с изменёнными полями, чтобы показать «было → стало».
- Фронт после `done` обновляет список и подсвечивает записи из `items`.

#### `clarify` — не хватает обязательного поля [ФТ 11]

```json
{
  "type": "clarify",
  "reply": "На какое время поставить встречу с Иваном?",
  "items": [],
  "options": [],
  "data": {
    "expects": "time",
    "draft": { "type": "meeting", "title": "Встреча с Иваном", "start_at": null, "participants": ["Иван"], "date_hint": "2026-10-30" },
    "attempt": 1
  },
  "undo_token": null,
  "suggestions": []
}
```

- `data.expects`: `time` | `date` | `datetime` | `title` | `yes_no` | `intent_choice`. Фронт может подстроить подсказку или варианты.
- `data.draft` можно показать полупрозрачной карточкой-черновиком.
- `data.attempt`: после второй неудачи бэкенд сбрасывает черновик и отвечает `info` **[ФТ 11]**.
- Неоднозначное намерение («Создать задачу про договор или найти существующую?») — тоже `clarify` с `expects: "intent_choice"` и кнопками **[ФТ 4]**.

#### `choose` — подходит несколько записей [ФТ 9, 10]

```json
{
  "type": "choose",
  "reply": "Нашёл две встречи с Иваном. Какую?",
  "speak": "Нашёл две встречи с Иваном. Назовите номер.",
  "items": [ { "number": 1, "id": "a1", "…": "…" }, { "number": 2, "id": "a2", "…": "…" } ],
  "options": [ { "id": "pick_1", "label": "1" }, { "id": "pick_2", "label": "2" } ],
  "data": { "pending_intent": "update" },
  "undo_token": null,
  "suggestions": []
}
```

Номера сохраняются как кандидаты и работают дальше: «вторую», «удали вторую».

#### `confirm` — нужно «да/нет» [ФТ 10, 11]

```json
{
  "type": "confirm",
  "reply": "Удалить встречу с командой, пятница 30 октября, 15:00?",
  "items": [ { "id": "b7", "…": "…" } ],
  "options": [ { "id": "yes", "label": "Да, удалить" }, { "id": "no", "label": "Нет" } ],
  "data": { "pending_intent": "delete", "count": 1 },
  "undo_token": null,
  "suggestions": []
}
```

Используется для удаления (всегда), массового удаления (`count` > 1), дубликата при создании **[ФТ 6]**, времени в прошлом («10:00 сегодня уже прошло. Поставить на завтра?») **[ФТ 5]** и вопроса «Только эту или все следующие?» для повторов (тогда `options` другие).

#### `conflict` — пересечение встреч [ФТ 12, FR-11]

```json
{
  "type": "conflict",
  "reply": "В это время уже есть встреча с командой, 15:00–16:00. Всё равно добавить?",
  "items": [ { "id": "c3", "title": "Встреча с командой", "…": "…" } ],
  "options": [ { "id": "yes", "label": "Всё равно добавить" }, { "id": "no", "label": "Другое время" }, { "id": "free_slot", "label": "Свободно с 16:00" } ],
  "data": { "draft": { "type": "meeting", "title": "Созвон с заказчиком", "start_at": "2026-10-30T15:30:00+03:00", "end_at": "2026-10-30T16:30:00+03:00" }, "free_slot": "2026-10-30T16:00:00+03:00" },
  "undo_token": null,
  "suggestions": []
}
```

`free_slot` и третья кнопка — только если сделан пункт Could из **[ФТ 12]**.

#### `results` — список за период или поиск [ФТ 8, 9]

```json
{
  "type": "results",
  "reply": "Завтра: в 10:00 напоминание позвонить Ивану, в 15:00 и 17:00 встречи, и две задачи.",
  "items": [ /* Item, уже отсортированы по правилам [ФТ 8] */ ],
  "options": [],
  "data": {
    "kind": "list",
    "from": "2026-10-30T00:00:00+03:00",
    "to": "2026-10-31T00:00:00+03:00",
    "types": null,
    "total": 5,
    "shown": 5,
    "overdue": [],
    "answer": null,
    "query": null,
    "semantic": true
  },
  "undo_token": null,
  "suggestions": [ "А на послезавтра?" ]
}
```

| Поле `data` | Комментарий |
|---|---|
| `kind` | `list` \| `search` \| `next` («когда следующая встреча?») \| `free_check` («я свободен завтра в 15?») |
| `total`, `shown` | всего найдено и сколько пришло: до 10 для списка, до 5 для поиска **[ФТ 8, 9]** |
| `overdue` | просроченные открытые задачи для запроса «на сегодня» **[ФТ 8]** |
| `answer` | для вопросов да/нет: `true` / `false` («Есть ли встречи сегодня?» → «Нет») |
| `query` | тема поиска |
| `semantic` | `false`, если смысловой поиск недоступен и искали только по словам **[ФТ 15]** |

Для `kind: search` у записей в `items` есть `number` (1–5), чтобы на них можно было ссылаться дальше. Группировку по дням делает фронт по `items`.

Пустой результат — тоже `results`, с `items: []` и `reply` «На завтра ничего не запланировано».

#### `info` — ответ без действия

```json
{ "type": "info", "reply": "Хорошо, не добавляю.", "items": [], "options": [], "data": { "reason": "cancelled" }, "undo_token": null, "suggestions": [] }
```

`data.reason`: `cancelled` (отмена диалога) | `help` («что ты умеешь?») | `out_of_scope` («какая погода?») | `draft_dropped` (черновик сброшен после двух неудач) | `already_done` («эта задача уже выполнена»).

#### `error` — не получилось [ФТ 15]

```json
{
  "type": "error",
  "reply": "Не получилось обработать запрос. Попробуйте ещё раз.",
  "items": [],
  "options": [],
  "data": { "code": "llm_unavailable", "retryable": true },
  "undo_token": null,
  "suggestions": [ "Что у меня сегодня?" ]
}
```

`data.code`: `empty_speech` | `not_found` | `llm_unavailable` | `llm_bad_output` | `db_error` | `internal`.

`/api/message` отвечает HTTP 200 и в случае ошибки — она в `type: "error"`. Ошибки, которые фронт обрабатывает сам (нет доступа к микрофону, браузер не поддерживает распознавание), сюда не попадают.

### 2.3 Записи — ручные действия без LLM

Клики в интерфейсе (галочка, перенос, удаление, редактирование) идут напрямую сюда, без модели и без задержки на её ответ.

| Метод | Путь | Что делает |
|---|---|---|
| `GET` | `/api/items?from=…&to=…&types=meeting,task&status=open&include_overdue=true` | записи за период; фильтры необязательные |
| `GET` | `/api/items/undated?types=task` | задачи без срока **[ФТ 8]** |
| `GET` | `/api/items/search?q=договор&limit=5` | тот же поиск, что у ассистента |
| `GET` | `/api/items/:id` | одна запись |
| `POST` | `/api/items` | создать вручную; бэкенд проверяет конфликты и отвечает `409` с конфликтующими записями |
| `PATCH` | `/api/items/:id` | частичное изменение: `{ "start_at": "…" }`, `{ "status": "done" }`, `{ "remind_at": "…" }` (отложить напоминание) |
| `DELETE` | `/api/items/:id` | мягкое удаление; в ответе `undo_token` |
| `POST` | `/api/undo` | `{ "undo_token" }` — отменить последнее действие (FR-15) |

Повторяющиеся записи: `PATCH` и `DELETE` принимают `?scope=this|following` и дату вхождения `&date=2026-11-02` **[ФТ 12]**.

Ответ списков:

```json
{ "items": [ /* Item */ ], "total": 9, "overdue": [ /* Item */ ] }
```

После ручного действия бэкенд делает эту запись фокусом сессии, чтобы «перенеси её» работало и после клика.

### 2.4 История и сессия

| Метод | Путь | Что делает |
|---|---|---|
| `GET` | `/api/history?session_id=…` | история диалога после перезагрузки страницы **[ФТ 3]** |
| `POST` | `/api/session/reset` | «Новый диалог»: сбросить контекст, записи остаются |

Элемент истории: `{ "role": "user" | "assistant", "text", "response": <ответ из 2.1 или null>, "at" }`.

### 2.5 Напоминания и события (SSE) — FR-13

`GET /api/stream` — поток для открытой страницы.

```
event: reminder
data: {"item": { "id": "r1", "type": "reminder", "title": "Позвонить Ивану", "remind_at": "2026-10-30T10:00:00+03:00" }, "reply": "Напоминаю: позвонить Ивану."}

event: items_changed
data: {"ids": ["7f3c…"]}
```

- На `reminder` фронт добавляет сообщение ассистента в историю, играет звук и озвучивает, если включено **[ФТ 12]**. Ответы «сделано» и «напомни через 15 минут» обрабатываются как обычные сообщения: напоминание становится фокусом диалога. Кнопки на карточке идут через `PATCH`.
- `items_changed` — запись изменилась не из этой вкладки.

`GET /api/reminders/missed?since=…` — напоминания, сработавшие, пока страница была закрыта. Фронт показывает «Пока вас не было: …» при открытии.

### 2.6 Пользователи — FR-12, [ФТ 13]

| Метод | Путь | Тело / ответ |
|---|---|---|
| `POST` | `/api/auth/register` | `{ "login", "password" }` → `{ "token", "user" }` |
| `POST` | `/api/auth/login` | `{ "login", "password" }` → `{ "token", "user" }` |
| `POST` | `/api/auth/guest` | → `{ "token", "user" }`, новый гостевой пользователь для демо |
| `POST` | `/api/auth/logout` | сбрасывает контекст диалога |
| `GET` | `/api/me` | `{ "id", "login", "timezone", "settings": { "speak": true } }` |
| `PATCH` | `/api/me` | `{ "timezone": "Europe/Moscow" }` |

Все запросы — с `Authorization: Bearer <token>`. Сессия живёт 7 дней. Пока вход не сделан, бэкенд считает всех пользователем `u_demo`.

### 2.7 Ошибки HTTP (кроме `/api/message`)

```json
{ "error": { "code": "not_found", "message": "Запись не найдена" } }
```

`400` валидация, `401` нет входа, `404` нет записи (в том числе чужая — без признака, что она существует **[ФТ 13]**), `409` конфликт встреч или версии, `500` внутренняя.

## 3. Контракт: бэкенд ↔ LLM-модуль

LLM **только** разбирает фразу в структуру. Она не ходит в базу, не выполняет действий и не пишет итоговый ответ о выполнении.

### 3.1 Что бэкенд отправляет

```json
{
  "text": "Поставь встречу с Иваном завтра",
  "now": "2026-10-29T12:00:00+03:00",
  "timezone": "Europe/Moscow",
  "anchors": {
    "today": "2026-10-29", "weekday": "thu",
    "tomorrow": "2026-10-30", "day_after_tomorrow": "2026-10-31",
    "this_week": ["2026-10-26", "2026-11-01"],
    "next_week": ["2026-11-02", "2026-11-08"],
    "last_week": ["2026-10-19", "2026-10-25"],
    "this_weekend": ["2026-10-31", "2026-11-01"],
    "month_end": "2026-10-31",
    "next_weekday": { "mon": "2026-11-02", "tue": "2026-11-03", "wed": "2026-11-04", "thu": "2026-10-29", "fri": "2026-10-30", "sat": "2026-10-31", "sun": "2026-11-01" },
    "following_week_weekday": { "fri": "2026-11-06", "thu": "2026-11-05" }
  },
  "history": [ { "role": "user", "text": "…" }, { "role": "assistant", "text": "…" } ],
  "expects": null,
  "draft": null,
  "focus": { "id": "7f3c…", "type": "meeting", "title": "Встреча с командой", "start_at": "2026-10-30T15:00:00+03:00" },
  "candidates": null
}
```

- **Опорные даты считает бэкенд**, модель только выбирает нужную. Так меньше ошибок с днями недели.
- «В четверг», когда сегодня четверг: сегодня, если время не указано или ещё впереди, иначе через неделю **[ФТ 5]**. В `next_weekday.thu` бэкенд кладёт сегодня, а модель по правилу из промпта выбирает `following_week_weekday.thu`, если время уже прошло. **[решить]** — проще ли сделать это правило в коде бэкенда после ответа модели.
- `history` — последние 5 реплик **[ФТ 11]**.
- `expects` — чего ждёт ассистент: `time`, `yes_no`, `number`… Только тогда фраза вроде «в 15» считается ответом **[ФТ 4]**.
- `draft`, `focus`, `candidates` — из состояния сессии (раздел 4).

### 3.2 Что LLM-модуль возвращает

```json
{
  "status": "needs_clarification",
  "actions": [
    { "intent": "create_meeting",
      "params": { "title": "Встреча с Иваном", "participants": ["Иван"], "date": "2026-10-30", "time": null, "duration_min": null, "location": null } }
  ],
  "missing": ["time"],
  "question": "На какое время поставить встречу с Иваном?",
  "options": []
}
```

- `status`: `ready` | `needs_clarification` | `not_understood`.
- `actions` — обычно одно действие. Несколько — только если это все `create_*` **[ФТ 4]**. Смесь создания с изменением — модель возвращает одно, первое, действие и флаг `"one_at_a_time": true`, бэкенд добавляет в ответ «Давайте по очереди».
- Модель отдаёт **дату и время раздельно** (`date`, `time`) и длительность в минутах. Перевод в `start_at`, `end_at`, `due_at`, период и UTC делает бэкенд — это проще проверять и тестировать.
- Неверная структура ответа — бэкенд повторяет запрос один раз, затем `error` с кодом `llm_bad_output` **[ФТ 15]**.

### 3.3 Намерения и параметры — по [ФТ 4]

| `intent` | `params` | Обязательные для `ready` |
|---|---|---|
| `create_task` | `title`, `date`, `time`, `period` (`this_week` \| `next_week` \| `month` \| `{from, to}`), `participants`, `recurrence` | `title` |
| `create_reminder` | `title`, `date`, `time`, `recurrence`, `for_meeting` (target, для «напомни за час до встречи») | `title`, `date`, `time` |
| `create_meeting` | `title`, `date`, `time`, `end_time`, `duration_min`, `all_day`, `participants`, `location`, `recurrence`, `remind_before_min` | `title`, `date`, `time` |
| `list` | `from`, `to`, `types`, `status`, `kind` (`list` \| `next` \| `free_check`), `yes_no` | `from`, `to` (кроме `next`) |
| `search` | `query`, `participant`, `types`, `from`, `to`, `status`, `direction` (`past` \| `future` \| `any`) | `query` или `participant` |
| `update` | `target`, `changes` | `target`, хотя бы одно поле в `changes` |
| `delete` | `target` | `target` |
| `complete` | `target`, `done` (`true` / `false` для «верни в работу») | `target` |
| `answer` | `value` (`{time}`, `{date}`, `true/false`, `{numbers: [2]}`, или поля черновика) | только при непустом `expects` |
| `cancel` | — | — |
| `undo` | — | — |
| `help` | — | — |
| `unknown` | — | — |

**`changes` для `update`** (по таблице **[ФТ 10]**): `date`, `time`, `shift_min` («на час позже» → `60`), `duration_min`, `title`, `participants_add`, `participants_remove`, `clear_due` (`true` для «убери срок»), `type` («сделай это встречей»).

**`target`** — какую запись имеет в виду пользователь. Порядок как в **[ФТ 10]**:

```json
{ "ref": "candidate", "numbers": [2] }
{ "ref": "focus" }
{ "ref": "filter", "query": "с Иваном", "participant": "Иван", "types": ["meeting"], "from": null, "to": null, "status": "open", "all": false }
```

`all: true` — массовое действие («удали все задачи на завтра»).

## 4. Состояние сессии (хранит бэкенд, Redis) — [ФТ 11]

```json
{
  "session_id": "s_abc123",
  "user_id": "u_1",
  "history": [ /* последние 10 реплик */ ],
  "draft": { "intent": "create_meeting", "params": { "…": "…" }, "missing": ["time"], "attempt": 1, "expires_at": "2026-10-29T12:10:00+03:00" },
  "expects": "time",
  "candidates": [ { "number": 1, "id": "a1" }, { "number": 2, "id": "a2" } ],
  "focus_id": "7f3c…",
  "pending": { "intent": "delete", "item_ids": ["b7"] },
  "processed_messages": { "c_01HF3…": "<ответ>" }
}
```

| Элемент | Живёт до |
|---|---|
| `history` | конца сессии |
| `draft` | выполнения, отмены, новой темы или 10 минут без ответа |
| `expects`, `pending` | ответа пользователя |
| `candidates` | следующего показанного списка |
| `focus_id` | смены фокуса |
| `processed_messages` | например, 10 минут (защита от двойной отправки) |

Подтверждением считаются только слова из списка **[ФТ 11]**. Любая другая фраза — новая команда, `pending` сбрасывается.

## 5. Сквозные сценарии

**Уточнение** (приёмка #6)
1. «Поставь встречу с Иваном завтра» → LLM: `needs_clarification`, `missing: [time]` → фронт: `clarify`.
2. «В 17» → LLM: `answer {time: "17:00"}` → бэкенд дополняет черновик, проверяет конфликты → `done`.

**Контекст** (приёмка #18)
1. «Перенеси встречу с командой на послезавтра» → `update`, target по фильтру, одна запись → `done` с before/after, она становится фокусом.
2. «А сдвинь её на час позже» → `update {target: focus, changes: {shift_min: 60}}` → `done`.

**Удаление** (приёмка #20, #21)
1. «Удали встречу с дизайнером» → одна запись → `confirm`.
2. «Да» → `done` (`deleted`) с `undo_token`. Если вместо «да» — «Что в ней?», удаления нет, обрабатывается новая фраза.

**Клик + голос**
1. Пользователь кликает по записи → фронт запоминает `selected_item_id`.
2. «Перенеси её на завтра» → бэкенд делает её фокусом → `update {target: focus}`.

**Сбой LLM** [ФТ 15]
1. Модель не ответила за 15 секунд **[решить]** → `error`, `llm_unavailable`, ничего не записано.
2. Бонус (раздел 6): до ошибки бэкенд пробует разбор правилами.

## 8. Открытые вопросы на созвон

Из ФТ (раздел 17) — решения по умолчанию там уже приняты, нужно подтвердить:
1. «Вы» или «ты».
2. Напоминание без времени: спрашивать или 09:00.
3. «В 3» без уточнения: 15:00 или переспрашивать.
4. Удаление: всегда подтверждать или только при неоднозначности.
5. «На этой неделе» в списке: с текущего момента или с понедельника.
6. Вход: логин и пароль, только гость или имя без пароля.
7. Делаем ли Could.
8. Список записей: боковая панель или основная часть экрана (см. раздел 6).
9. Хранить историю диалога между сессиями.

Технические:
10. База: PostgreSQL + pgvector или SQLite. Где храним эмбеддинги.
11. Какая LLM и какая модель эмбеддингов.
12. Распознавание речи в браузере (Web Speech) или на сервере.
13. Тайм-аут LLM: 15 секунд, как в ФТ, или меньше.
14. Правило «в четверг, когда сегодня четверг»: в промпте или в коде бэкенда.
15. Как импортируем присланный CSV и определяем тип записей из него.
16. Формулировка ответа: шаблоны из [ФТ 14] или второй вызов LLM с шаблоном как запасным вариантом.
17. Напоминание за 15 минут до встречи по умолчанию.
18. Как меняем документы: только через PR с повышением версии.
