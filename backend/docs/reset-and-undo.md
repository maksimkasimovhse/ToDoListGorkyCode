# Сброс диалога и отмена действий

Оба маршрута требуют Authorization: Bearer <token>. Фронтенд не изменён.

## POST /api/session/reset

```json
{"session_id":"s_идентификатор_диалога"}
```

Ответ 200: {"ok":true}.

Сбрасываются только контекст и ожидания указанного диалога текущего пользователя:
история для контекста ML, черновик, выбор кандидатов и фокус.
Активное сообщение processing/awaiting_input/awaiting_confirmation переводится в cancelled,
input_token очищается. Запоздавший ответ ML после сброса не применяется.
Записи items не изменяются и не удаляются. Undo уже выполненных действий сброс не выполняет.

Архивные messages сохраняются в БД. /api/history для сброшенного session_id показывает только
сообщения, принятые после сброса. Старые сообщения своего пользователя доступны по message_id.
Можно продолжить с тем же session_id или создать новый на фронте. Повторный сброс безопасен;
неизвестный session_id возвращает ok без создания диалога. Пустой/длинный session_id — 400.
Сброс одного пользователя не меняет одноимённый диалог другого.

Сброс и обработка ML блокируют одну строку conversations. Если операция успела завершиться
до сброса, её записи сохраняются; если первым завершился сброс, поздняя команда не выполняется.

## Откуда брать undo_token

- Успешный POST /api/items: поле undo_token в возвращаемом объекте Item.
- Успешный PATCH /api/items/{id}: поле undo_token в возвращаемом Item.
- DELETE /api/items/{id}: теперь **200** с {"undo_token":"undo_..."}, вместо прежнего 204.
- Завершённая команда сообщения/ответа на уточнение: response.undo_token.

Создание, изменение, выполнение/возврат в работу и мягкое удаление поддерживают отмену.
Составная команда из нескольких create_* имеет один токен: отменяется весь набор записей.
Для search/list, уточнений, выбора и отказа от действия токен не создаётся.
Токен принадлежит пользователю, а не конкретной сессии входа: после повторного входа тот же
владелец может его использовать. Другой пользователь получает 404.

## POST /api/undo

```json
{"undo_token":"undo_секретный_токен_из_ответа"}
```

Ответ 200 — стандартный объект ответа ассистента:

```json
{
  "type":"done",
  "reply":"Отменил действие.",
  "items":[],
  "options":[],
  "data":{"actions":[]},
  "undo_token":null,
  "speak":null,
  "suggestions":[]
}
```

В реальном ответе items и data.actions содержат изменённые записи и before/after.
Фронт после ответа должен перечитать список. Отмена создания выполняет мягкое удаление,
отмена изменения восстанавливает прежние поля, отмена удаления — прежнюю запись с тем же id.
Статус, completed_at, сроки, участники и напоминание также восстанавливаются.

Токен действует 10 минут до первого успешного применения. Повтор успешного /undo возвращает
сохранённый ответ, не изменяя записи повторно. Отмена отмены (redo) не создаётся.

Ошибки:

- 400 validation — неверный формат токена;
- 404 not_found — токен отсутствует или принадлежит другому пользователю;
- 410 undo_expired — срок неиспользованного токена истёк;
- 409 undo_conflict — запись изменилась после исходного действия, включая другое undo;
- 409 meeting_conflict — восстановление встречи конфликтует с другими текущими встречами.

При конфликте ничего не откатывается, в том числе в составной операции. Токен не расходуется:
после освобождения времени восстановление удалённой встречи можно повторить.
Автоматического обхода конфликтов через allow_conflicts для /undo нет.

## Хранение и транзакции

Новая CREATE-миграция 00005_create_undo_and_resets.sql создаёт undo_operations и conversation_resets.
Старые миграции не меняются. В undo_operations хранятся хеш токена, владелец, снимки before/after,
срок, время применения и ответ. Запись операции фиксируется вместе с изменениями items.
Токен ответа и вычисляемые поля не входят в снимки состояния.

Отмена выполняется под общей блокировкой расписания пользователя. Сначала проверяются все
версии updated_at и конфликты, затем восстанавливаются все записи и сохраняется ответ.
Параллельные запросы с одним токеном выполняют изменение только один раз.
Сброс сохраняет отметку времени для фильтрации архива, контекст и отмену активного сообщения
одной PostgreSQL-транзакцией. Redis здесь не является источником состояния.
