# Блокировка диалога и ответы из формы

Один message_id представляет весь сценарий, включая уточнения и подтверждения.
Новый POST /api/message в том же session_id запрещён при processing, awaiting_input
и awaiting_confirmation: сервер отвечает 409 conversation_busy. Ограничение действует
также в БД и не зависит от корректности фронтенда.

## Поведение фронта

1. После приёма сообщения блокировать обычный ввод и опрашивать GET /api/messages/{id}.
2. При awaiting_input открыть форму по response.data.expects. Сохранить input_token.
3. При awaiting_confirmation открыть подтверждение. Сохранить input_token.
4. Отправить структурированные поля через /answer. Ответ содержит тот же message_id.
5. Если нужны другие поля, заменить окно и input_token, сохраняя блокировку диалога.
6. Разблокировать ввод только при completed, failed или cancelled.

В состояниях ожидания формы частый polling не нужен; deadline_at показывает срок ожидания.
При перезагрузке GET /api/history?session_id=... возвращает активный сценарий в
pending_messages, включая response, input_token и deadline_at. Фронт восстанавливает окно.
Обычный GET /api/messages/{id} также возвращает актуальное состояние.

## Уточнение

```http
POST /api/messages/{message_id}/answer
Content-Type: application/json
```

```json
{
  "input_token": "55da981b-0965-4684-a903-ddf3f0d54386",
  "time": "17:00",
  "duration_min": 30
}
```

Разрешены date (YYYY-MM-DD), time (HH:MM), title, duration_min. Нужно передать ожидаемое
поле из response.data.expects. Можно заполнить несколько известных полей одновременно.
Ответ 200 содержит актуальную обёртку сценария. Если нужен следующий шаг формы,
сервер возвращает awaiting_input и новый input_token.

Поля проверяются и дополняют сохранённый черновик в Go; новый запрос модели не отправляется.
Сохранение записи, ответа, контекста и отметки о принятом token выполняется одной транзакцией.

## Подтверждение

Тот же маршрут /answer, но только с input_token и confirmed:

```json
{
  "input_token": "55da981b-0965-4684-a903-ddf3f0d54386",
  "confirmed": true
}
```

Для подтверждения конфликта (data.reason = meeting_conflict) confirmed false сохраняет черновик
и переводит в awaiting_input: «Хорошо. На какое время поставить?». Отправьте новое time
с новым input_token; длительность сохраняется, конфликты проверяются заново.
В остальных подтверждениях confirmed false отменяет сценарий и возвращает cancelled.
Полная отмена в любом состоянии — через /cancel. Поля записи нельзя смешивать
с confirmed в одном ответе.

## Отмена и срок ожидания

POST /api/messages/{message_id}/cancel без тела отменяет активный сценарий, включая processing.
Ответ 200 содержит cancelled. Повтор отмены уже отменённого сценария безопасен.
Отмена завершённого действия возвращает 409 message_state: сохранённые записи не удаляются.
Поздний ответ ML после отмены не выполняет команду.

Срок ожидания черновика — десять минут; актуальный момент указан в deadline_at.
По истечении сценарий получает failed с response.data.code=input_timeout, черновик удаляется,
диалог освобождается. Ответ, пришедший после срока, не сохраняет запись.

## Повторы и ошибки

- 400 validation: неверные или недостающие поля; окно остаётся открытым, token не меняется.
- 409 stale_input: token от устаревшего окна; перечитать текущий сценарий.
- 409 message_state: сценарий не ожидает ответа либо уже завершён.
- 409 idempotency_conflict: ранее принятый token повторён с другими полями.
- 404 not_found: сценарий отсутствует или принадлежит другому пользователю.

Повтор уже принятого token с тем же содержимым возвращает актуальный сценарий без
повторного выполнения. При потере HTTP-ответа повторять запрос с исходными token и телом.
Нельзя подставлять новый token в старый сетевой повтор. input_token не заменяет авторизацию.

## Выбор записи

Для response.type choose используется awaiting_input. В /answer передаются input_token и
либо option_id, либо text (например «вторую»). Для choose нельзя показывать форму времени.
После ответа возможны done, confirm или обновлённый choose. См. [контракт](selection.md).
