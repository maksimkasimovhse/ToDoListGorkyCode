# Модель и смысловой поиск

`ml-worker` заменяет заглушку правил и использует прежние Redis Streams. Go публикует
текст и контекст диалога, worker возвращает только структурированные действия. ID пользователя,
Bearer-токен и SQL модели не передаются; владельца и допустимость команды проверяет backend.

Для поиска Go сначала применяет обычные фильтры пользователя, типа, статуса и периода.
Затем внутренний endpoint worker получает запрос и тексты не более 99 отфильтрованных записей,
вызывает `Embeddings-2`, а Go объединяет semantic score с совпадениями по словам. При ошибке
embedding API запрос не падает: возвращается прежний поиск по словам и `semantic: false`.

## Настройка

Скопируйте `.env.example` в `.env` и задайте один секрет:

```env
GIGACHAT_AUTH_KEY=...
# либо GIGACHAT_ACCESS_TOKEN=...
```

`docker compose up --build` запускает backend, PostgreSQL, Redis и `ml-worker`.
XLSX с ключом в образ не добавляется. `MESSAGE_TIMEOUT` увеличен до 90 секунд, потому что
структурированный разбор может требовать несколько последовательных запросов к модели.

Текущая реализация рассчитывает векторы при поиске и рассчитана на прототип до 99 записей
после обязательных фильтров. Для большого объёма следующим шагом нужна отдельная таблица
индекса и фоновая индексация (например, pgvector), без изменения публичного API.
