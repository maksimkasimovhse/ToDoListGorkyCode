# Бэкенд голосового ассистента

Запускаемый каркас на Go 1.26 без внешних зависимостей. Сейчас реализован только HTTP healthcheck. БД, LLM, авторизация и API записей пока не подключены.

## Запуск

Из папки `backend`:

```powershell
go run ./cmd/api
```

Проверка: `GET http://localhost:8080/healthz` возвращает `200` и `{"status":"ok"}`. Это проверка жизни процесса, а не готовности зависимостей.

Настройки читаются из окружения; `.env.example` служит примером, `.env` автоматически не загружается.

```powershell
$env:HTTP_ADDR = ':8080'
$env:SHUTDOWN_TIMEOUT = '10s'
go run ./cmd/api
```

Ctrl+C завершает сервер с ожиданием текущих запросов в пределах `SHUTDOWN_TIMEOUT`.

## Структура

```text
cmd/api/                 точка входа и сигналы завершения
internal/app/            сборка зависимостей и жизненный цикл
internal/config/         конфигурация из окружения
internal/domain/         сущности и типы предметной области
internal/repository/     интерфейсы доступа к данным
internal/service/        сценарии приложения (пока только пакет)
internal/transport/http/ маршрутизация и HTTP-обработчики
migrations/              будущие миграции БД
```

HTTP-обработчики будут вызывать сервисы; сервисы — интерфейсы репозиториев и LLM. Реализации подключаются в `internal/app`. Доменные сущности не зависят от HTTP и SQL. Форматы API и модели следует описывать отдельными DTO.

Модель записи основана на ФТ: задача, напоминание, встреча; срок задачи необязателен. Повторы пока не включены. Интерфейс репозитория предварительный и будет уточняться при реализации сценариев; реализации хранилища сейчас нет.
